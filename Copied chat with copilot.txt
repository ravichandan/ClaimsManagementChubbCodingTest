The topic names are not the problem.

Your Kafka topics are defined as:

- `claim-events`

The actual failure is that the app is trying to reach Kafka at `localhost:9092`, which is shown in the log:

> Connection to node -1 (localhost/127.0.0.1:9092) could not be established

That matches the default config in `application.properties`, not the dev profile in `application-dev.properties`, which uses `localhost:29092`.

---

## Why this happens

Your app is likely running without Kafka actually started, or without the correct Spring profile enabled.

The Docker config in `docker-compose.yml` defines Kafka on:

- `localhost:9092`
- `localhost:29092`

So if Kafka is not running, `KafkaAdmin` fails to configure topics exactly as you’re seeing.

---

## Fix

### 1) Start Kafka
From the project root:

```bash
docker compose up -d zookeeper kafka
```

Then confirm it is listening:

```bash
docker compose ps
```

and optionally:

```bash
nc -vz localhost 9092
```

### 2) Ensure the right profile is active
If you intend to use the Docker-based Kafka config, run:

```bash
SPRING_PROFILES_ACTIVE=dev ./gradlew bootRun
```

or:

```bash
./gradlew bootRun --args='--spring.profiles.active=dev'
```

That will use the `localhost:29092` setting from `application-dev.properties`.

---

## Bottom line

This is not a topic naming issue. It is a Kafka broker connectivity issue.
